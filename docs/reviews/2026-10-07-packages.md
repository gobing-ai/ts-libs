## Reproduction evidence

Inline Bun probes executed against the source during this review:

- DAG failure: a guard waited until its deferred sibling started, then threw. The run rejected with sibling unfinished and persisted status `failed`; releasing the sibling then caused its action to finish after run rejection.
- DAG recovery: completed node `a`, blocked rerun-safe node `b`, and interrupted the owner. Ledger rows were `done`/`running`, snapshot was undefined, and `resumeRun` rejected with `has no persisted state to resume from`.
- DAG pause: a counted action on a `pause: true` node executed zero times across initial pause and successful skip-enter resume.
- DAG scheduling: independent fast/slow roots plus a child depending only on fast produced `start:fast, start:slow, end:fast, end:slow, start:child, end:child`.
- Decision validation: a fake driver returned a two-level score distribution `{0: 0, 1: 0}` and `ask` accepted it.
- Deadline helper: three settled calls on one signal added three listeners and removed zero before the fix.
- Async once: `emit` returned while a deferred handler remained unfinished before the fix.
- Duplicate registration: registration threw for a duplicate name, but the rejected event still had one listener and executed it before the fix.
- Invalid date: the pre-fix result was NaN; the regression now expects null.

## Architecture assessment

The direct workspace dependency graph is acyclic, and every direct internal dependency uses `workspace:*`. The optional runtime-to-db peer seam remains sanctioned by ADR-012; it is not a new direct dependency cycle. The decision driver direction, portable infra barrel, DB facade/schema seam, and browser launcher exception were reviewed against ADRs. No additional architecture refactor is proposed without a concrete defect.

The concrete structural finding is the DAG wave barrier. A small in-flight set with readiness reconsidered on completion is sufficient; it must retain the drain invariant from 0103. Durable recovery should reuse existing per-node output and snapshot adapter seams before considering a schema change.

# C1: Workflow YAML rule-style extensions

## Goal
The workflow definition schema accepts a rule-style extensions block listing relative action and guard modules, so a YAML file can declare extra kinds the same way a rule preset declares evaluators.
## Scope
- In:
  - `extensions.actions` and `extensions.guards` string arrays on both state-machine and transition-flow `WorkflowDef` (Zod + packaged JSON schemas)
  - Path rules identical to rule-engine `relativeExtensionPath`: relative to the workflow file, no absolute paths, no `..`
  - `collectWorkflowExtensions(sourceName, sourceDir, extensions)` producing `WorkflowExtensionRef[]` for `loadWorkflowExtensionsIntoHost`
  - Types exported from `@gobing-ai/ts-dual-workflow-engine`
  - README + schema docs
- Out:
  - CLI wiring (`spur workflow validate|run`) — spur-new D4
  - New built-in action/guard kinds
  - Absolute / home-dir paths
  - Product-plugin (`plugin.json`) discovery

    - Live integration/CI smoke that calls xAI network

## Notes
# Design summary — Grok coding agent in `@gobing-ai/ts-ai-runner`


Add `grok` as a **tier-1** bundled coding agent (canonical id `grok`, binary `grok`), matching the existing `AgentShim` pattern (e.g. `claude`, `hermes`, `omp`).


| ai-runner surface | Grok CLI |
|---|---|
| help | `grok --help` |
| version | `grok --version` → `grok 0.2.93 (...)` (matches `AgentDetector` `VERSION_PATTERN`) |
| one-shot prompt | `grok -p <input>` (`--single`) |
| continue | `-c` / `--continue` |
| model | `-m` / `--model` |
| mode `text` | `--output-format plain` (Grok has no `text` value) |
| mode `json` | `--output-format json` |
| auth status verb | **none** — use env/file probe |

### Auth (tri-state, off critical path)

1. Non-empty `XAI_API_KEY` → `authenticated`
2. Non-empty `~/.grok/auth.json` → `authenticated`
3. Else → `unknown` (never false-negative `unauthenticated`)

`getAuthCommand()` → `null` (like `antigravity-cli`); no interactive `login` as a probe.

### Slash dialect

Default branch: `/plugin-command` (no Claude `:` or Codex `$` dialect observed as the primary skill surface for headless).

### Out of scope

- Live network smoke against xAI in CI
- Team-mode `grok agent stdio` long-running process nuances
- Subagent / best-of-n / worktree flag pass-through (future PromptOptions expansion)


- `packages/ai-runner/src/agents/shims.ts` — type, shim, registry, orders
- `packages/ai-runner/src/agents/auth-shims.ts` — env/file auth
- `packages/ai-runner/tests/**` — shims, auth, detector/doctor, slash
- `packages/ai-runner/README.md` — supported agents list

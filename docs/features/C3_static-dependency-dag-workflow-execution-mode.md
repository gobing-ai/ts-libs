# C3: Static dependency DAG workflow execution mode

## Goal

Provide an explicit static dependency DAG execution mode within `@gobing-ai/ts-dual-workflow-engine` where nodes declare prerequisites (`dependsOn`) and are dispatched via a dependency-driven ready queue upon satisfaction, supporting conditional skip propagation, strict cycle rejection, and durable execution without altering existing FSM or transition-flow semantics.

## Scope

- In:
  - Workflow definition schema and ADR for static dependency DAG execution (`dependsOn` prerequisite declarations, dependency satisfaction policies).
  - Strict acyclic graph validation: cycle rejection at validation time (topological sort / cycle detection) while preserving legal loops in FSM and transition-flow modes.
  - In-process ready-queue scheduler: nodes become eligible when declared prerequisite conditions settle.
  - Conditional skip propagation: unselected conditional branches propagate skipped status to downstream dependents so join barriers do not deadlock.
  - Durable DAG node ledger tracking per-node status, attempt, and execution outcomes across pause/resume/interruption.
  - Observability events and trace instrumentation for DAG scheduling.
- Out:
  - Dynamic runtime graph expansion (graph topology remains static at load time).
  - Cycles in DAG mode (cycles remain supported in FSM and transition-flow modes).
  - Distributed multi-worker cluster execution.

```gherkin
Feature: Static dependency DAG workflow execution mode

  @core

    Given a DAG workflow definition
    When validated by validateWorkflowDef
    Then acyclic graphs pass and any cyclic dependency or undeclared dependency is rejected with a descriptive error

  @core
  Scenario: R2 — Dependency ready-queue scheduling
    Given a DAG workflow where node D depends on nodes A and B
    When the workflow executes
    Then node D is only dispatched after both A and B complete successfully

  @core
  Scenario: R3 — Conditional branch skip propagation
    Given a DAG workflow with conditional dependencies where an upstream branch is not taken
    When the workflow executes
    Then downstream nodes dependent on that branch are marked skipped and downstream joins evaluate completion policies without deadlocking

  @core
  Scenario: R4 — Durable DAG recovery
    Given a durable DAG workflow execution interrupted mid-run
    When resumed with valid ownership
    Then already-completed nodes are not re-executed and pending ready nodes resume cleanly
```

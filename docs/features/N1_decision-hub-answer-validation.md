# N1: Decision hub answer validation

## Goal

Ensure DecisionHub's fallback guarantee applies to answers from every registered maker, including directly supplied custom makers, by validating answers before confidence gating.

## Scope

- In: shared answer validation at the hub boundary, existing fallback/error mapping, and regression coverage for malformed custom answers and valid choice, fractional score and noul answers.
- Out: new maker APIs, catalog schemas, dependencies, calibration policy, timeouts, disposal concurrency, and changes to backend implementations.

## Acceptance Criteria

```gherkin
Feature: Decision hub answer validation

  Scenario: AC1 — Every maker's answer crosses validation
    Given a directly registered custom maker returning an undeclared choice label or NaN, infinite or out-of-range confidence
    When decide is called on a valid catalog decision
    Then the answer is rejected before confidence gating and the declared fallback is returned

  Scenario: AC2 — Fallback and caller errors remain distinct
    Given malformed backend answers
    When decide resolves
    Then source is default, reason is error, confidence is null and maker identifies the selected maker
    And unknown decisions, invalid inputs and unregistered per-call makers still throw before any maker ask

  Scenario: AC3 — Correspondence and valid values remain compatible
    Given missing or extra answer keys, invalid score bounds or invalid noul probability
    When a directly registered custom maker answers
    Then the hub returns the declared fallback
    And valid choice, fractional expected-score and noul answers remain accepted
    And focused hub tests, spur-check and build pass
```
